# school76 — DeepSeek-Harness

Платформа совместной разработки образовательного кубсата формата 1U на базе архитектуры **DeepSeek-Harness (Cordis)**: всё является плагином с обратимыми эффектами, швами возможностей (Three-Role Seams), профилями композиции и агентским циклом.

## Архитектура и возможности

- **Ядро DeepSeek-Harness (Cordis)** — модульный контейнер плагинов (`src/harness/cordis.ts`, `server/harness/runtime.ts`, `harness.profile.yaml`):
  - **Профили композиции** — переключение конфигураций (`cubesat-full`, `firmware-lab`, `headless-ci`, `sdk-minimal`) с автоматическим монтированием и откатом плагинов.
  - **Швы возможностей (Seams)** — независимые контракты (`dsh-store`, `dsh-forge`, `dsh-s3`, `dsh-ci`, `dsh-realtime`, `dsh-tools`, `dsh-llm`) с подменяемыми провайдерами.
  - **Агентский цикл и dsh-tools** — выполнение типизированных инструментов и многошаговых инженерных сценариев по задачам, wiki, CI, Маркетплейсу и ПО.
- **Маркетплейс оборудования и модулей** — установка и активация целевых контроллеров (`Auriga STM32`, `CyberPi ESP32`, `MeOrion AVR`, `mDrawBot Az-El`, `UHF SDR`), программных модулей портала (Cordis) и расширений `.mext` с динамическим обновлением палитры блоков mBlock.
- **Управление задачами** — доска (Канбан), таблица, календарь и Гант по подсистемам (`OBC`, `EPS`, `ADCS`, `COMMS`, `PAYLOAD`, `GROUND`).
- **mBlock Борт ПО** — визуальный конструктор на базе `blockly` (`zelos` renderer), трансляция в MicroPython и STM32 C++, онлайн-стенд 1U.
- **Техчат команды** — тематические каналы подсистем через WebSocket со списком участников онлайн.
- **Проекты и база знаний** — 3D-макет 1U, Forgejo `llm-wiki` с `[[wikilinks]]`, редактор Univer, Garage S3 и CI/CD.

## Запуск

```bash
pnpm install
pnpm dev
```

Сервер запускается на `http://localhost:3000`. Для production-сборки:

```bash
pnpm build
pnpm start
```

### PostgreSQL (WSL2 + Docker)

Состояние миссии (задачи, сообщения, программы ПО, пользователи, проекты, посты)
хранится в PostgreSQL 17. Без базы приложение тоже запускается — тогда
используется JSON-хранилище `data/school76.json`.

Инфраструктура поднимается из WSL:

```bash
docker compose up -d
```

PostgreSQL публикуется на `127.0.0.1:5433` (порт 5432 на этой машине занят
другими службами). Затем скопируйте `.env.example` в `.env` и укажите:

```dotenv
POSTGRES_HOST=127.0.0.1
POSTGRES_PORT=5433
POSTGRES_DB=school76_mission
POSTGRES_USER=school76
POSTGRES_PASSWORD=school76
```

`server/db/schema.sql` применяется автоматически при старте, поэтому повторный
запуск мигрирует существующую базу без потери данных. Если база пуста, сервер
один раз импортирует в неё текущее JSON-состояние. При недоступной базе сервер
пишет предупреждение и продолжает работать на JSON-хранилище.

Источник состояния виден в `GET /api/health` (поле `persistedTo`), а
`POST /api/postgres/query` выполняет `SELECT`-запросы к живой базе.
